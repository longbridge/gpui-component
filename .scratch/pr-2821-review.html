P0 · Security

文件系统 capability 可被符号链接绕过

Capabilities::resolve 只进行词法归一化与 starts_with(root) 检查，随后 std::fs 调用会跟随符号链接。若授权目录内存在 escape -> /etc，脚本可读取 escape/passwd；写权限同样可越界写入。代码注释声称 syscall 时会再次检查，但实现不存在。AppAssets 使用同一类词法检查，也可经 symlink 读取根目录之外的资源。

修复：使用 descriptor-relative/no-follow 文件操作，或在每次操作前 canonicalize 已存在祖先并再次验证 containment；写入需处理不存在的末级路径与 TOCTOU。增加 read/write/list/remove/create 与 asset symlink escape 测试。

crates/shell/src/capability.rs:112–135, 201–204 · crates/shell/src/engine/quickjs/host.rs:102–160 · crates/shell/src/assets.rs:36–62 · spec §19.2

P1 · Function

process.exit() 实际是成功的 no-op

调用只写入 EXIT_REQUEST；读取函数 take_exit_request 没有任何生产调用者。获准调用的脚本得到成功结果，但窗口、panel 和 CLI 都不会退出，与设计中“host polls for the code”不符。

修复：在所有脚本调用边界或 host 事件循环中消费退出请求，定义嵌入式 panel 与独立 CLI 的不同策略，并增加授权后的端到端退出测试。

crates/shell/src/engine/quickjs/sandbox.rs:307–343 · docs/gpui-shell.md:2027–2032

P1 · Perf

所有 gpui.fs 方法同步阻塞 UI/VM 线程

read_text、write_text、read_dir、exists、remove、create_dir_all 均在 QuickJS host callback 内直接执行同步系统调用。慢磁盘、网络卷或大文件会冻结事件处理并突破执行预算；源码中的 TODO 与设计文档都明确要求 promise 异步化。

修复：将 I/O 投递到 GPUI background executor，以 Promise 返回；限制读取大小，并验证调用不会同步占住主线程。

crates/shell/src/engine/quickjs/host.rs:17–24, 99–164 · docs/gpui-shell.md:1962–1965

P1 · Architecture

公开 host 控制 API 绕过可替换引擎 seam

set_capabilities、set_store_path、set_development_mode 从 crate 根直接调用 QuickJS 私有模块；非 QuickJS 构建则静默 no-op。第二个引擎即使编译成功，也可能无声忽略安全配置。

修复：把这些操作纳入 ShellRuntime/engine contract，删除静默 fallback；让不支持的配置在编译期或显式 Result 中失败，并为 feature 组合添加 compile tests。

crates/shell/src/lib.rs:48–84 · docs/gpui-shell.md:481–506, 550–565

P1 · A11y

行情行是仅鼠标可操作的自定义点击容器

每行使用 h_flex().on_click(...)，只有 hover 反馈，没有 focus handle、Tab stop、键盘 action、focus-visible 状态、role 或可访问名称。这违反项目“优先组合语义控件”和“每个动作可由键盘完成”的规范。

修复：使用语义化 selectable list/control，或完整实现 focused composite contract；补 pointer、Enter/Space、Tab 顺序与 focus-visible 测试。

crates/story/src/stories/shell_story.rs:952–967 · Coding Guides: Rendering and composition; Events, actions, and focus · Design Guides: Accessibility checklist

P2 · Zoom

修复：两侧建立同一 length/rem 模型，使用 spacing/type helpers 或主题 token，并在非默认 window.rem_size() 下验证。
