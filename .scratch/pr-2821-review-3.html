开放问题

P0 · Worktree

插件加载期异步任务丢失 Policy

Plugin load 以 view=None 进入 Policy，但 TaskState 只保存 owner/view。模块顶层或 init 中创建的 timer、spawn、sleep、async fs 恢复时回落到 DEFAULT Policy，可能获得默认应用的 fs/native/store 权限。InputState 长生命周期 subscription 也以 view=None dispatch，有相同缺口。

修复：任务与 subscription 创建时捕获 Rc<Policy>，恢复统一使用 enter_with；补双 Policy top-level await/timer/input 测试。

plugin.rs:947–955 · scheduler.rs:498–515,538–581 · entity_api.rs:133–148 · engine/quickjs/mod.rs:404–431

P1 · Worktree

插件 Store 完成回调修改默认 Store

detached completion 没有 scope，却调用 scope::policy() 查 Store。插件 Store 会永久停在 writing=true，后续 mutation 不再持久化。

修复：完成回调携带发起写入的 Policy/Store identity，禁止依赖 ambient lookup。

P1 · Commit

写入期间的最后一次 mutation 可能永久丢失

新 mutation 只标 dirty；完成回调观察 dirty 后没有排队下一次写。若之后没有 mutation，磁盘永远停在旧版本。

engine/quickjs/host.rs:303–343

P1 · Worktree

flush 与自动写并发，旧 revision 可覆盖新 revision

两条 persist 使用同一 <path>.tmp，并且没有 revision serialization。应改成 per-Store 串行队列；flush 是等待目标 revision 的 barrier。

P1 · Worktree

Native module 动态撤销不再对已有 view 生效

ScriptView 保存旧 Rc<Policy>，而 update_default copy-on-write 创建新 Policy；clear_native_modules 无法撤销旧 view 捕获的闭包。要么共享可变 registry，要么把契约改为 startup-only。

P1 · Docs

README/网站仍描述旧的同步 fs 与 flush API

实际 API 已 Promise 化，但英文、中文网站和部分设计风险表仍是旧状态，应用作者会写出错误调用方式。
