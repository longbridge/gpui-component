# Start from the Task and Mental Model

Before drawing a screen, write down:
- The user's primary task;
- The object being viewed or changed;
- The actions that must remain immediately available;
- The information required to make a decision;
- Empty, loading, error, offline, read-only, and permission-denied states;
- The keyboard path through the workflow.

Organize the window around those answers. Do not begin with a dashboard grid or a component catalogue. A good desktop interface exposes the user's mental model: documents, accounts, projects, messages, settings, or another stable object—not the internal service architecture.

## Primary Task Design

- Design the primary task before distributing controls. Its visual weight, location, and information depth should match its importance.
- When a result set is the product's main value, use a summary region or card that exposes the count, representative results, meaningful state, and a clear next action.
- For every proposed action, name its visible object, current state, scope, and result. If the interface does not show or clearly imply those things, the action is premature.
